# Backend — Ерасыл

Владелец `apps/api/`: **Ерасыл**. Рабочая ветка: **`yerasyl-branch-back`**.
Общие правила и проверка роли/ветки определены в корневом `AGENTS.md`; этот файл их дополняет.

- Реализуй единственный HTTP API на NestJS и TypeScript по `docs/CONTRACTS.md`.
- Обязателен TDD: до нового поведения или исправления ошибки напиши тест и убедись, что он падает по ожидаемой причине; затем минимальная реализация и рефакторинг при зелёных тестах. Следуй разделу TDD в `docs/prompts/erasyl-backend.md`.
- Python в `analytics/` — единственное место расчёта метрик, ролей, кластеров, приоритетов и CSV.
- Координируй изменения общих типов в `packages/contracts/` с Ильёй и аналитиком.
- В JSON сохраняй int64 идентификаторы и денежные суммы как строки; не преобразовывай их в JavaScript Number.
- Не добавляй БД, очереди, авторизацию, FastAPI или отдельный сервер аналитики без согласованного изменения объёма.
- Текущий каркас поддерживает `GET /api/health`; аналитические маршруты честно возвращают `501 PIPELINE_NOT_IMPLEMENTED`.
- Заменяй заглушки только проверенной интеграцией Python CLI; не создавай фиктивные успешные запуски или выгрузки.
- `health.status = ok` означает доступность API, а не готовность аналитики или выполнение требований ТЗ.
- При интеграции используй отдельный каталог запуска, `spawn` без shell и проверку всех артефактов до `completed`.
- Корневые команды запуска, Docker и README меняй согласованно с командой; чужие файлы сохраняй.
- Для проверки этой части из корня используй `npm run test --workspace @money-graph/api` после установки зависимостей и сборки contracts.
