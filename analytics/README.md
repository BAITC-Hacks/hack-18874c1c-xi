# Аналитика Money Graph

Независимый локальный Python CLI: три Parquet → валидация → метрики → кластеры и роли → приоритет → три CSV и `analysis.json`. Внешние модели, API-ключи, SciPy, HTTP-сервер и GPU для расчёта не нужны. Это реализация аналитической части, не подтверждение готовности NestJS/Next.js.

## Исходные материалы

- Рабочие данные: `data/nodes.parquet`, `data/edges.parquet`, `data/transactions.parquet` относительно корня Git-репозитория. Они исключены из Git; данные хакатона не публикуются автоматически.
- [Описание организаторов](../docs/references/organizers/DATASET.md) и [исходный starter](../docs/references/organizers/starter/README.md) сохранены как справочные материалы. Наш код находится в `analytics/src/money_graph`; `requirements.txt` starter отдельно не устанавливать.
- [Методология](../docs/METHODOLOGY.md): правила, пороги, формулы, ограничения и масштабирование. Параметры — [config.py](src/money_graph/config.py), контракт — [CONTRACTS.md](../docs/CONTRACTS.md).

## Запуск из корня репозитория

Установку закреплённых Python-зависимостей смотри в корневом README. После установки:

```sh
.venv/bin/python -m money_graph --input-dir data --output-dir artifacts/run-001
```

Или без локальной установки Python, через Docker:

```sh
docker compose --profile tools run --rm --build analytics --input-dir /data --output-dir /artifacts/run-001
```

Для каждого запуска выбирай новый каталог (`run-002` и далее) либо уже существующий **пустой**. Корневой `artifacts/` содержит `.gitkeep`, поэтому не подходит как пустой выходной каталог. CLI не стирает и не заменяет старые результаты. Входные данные монтируются в Docker только для чтения. Поддерживаемый воспроизводимый runtime — Python 3.12 в Docker; локально macOS/Linux и Windows (установка — в корневом README).

Четыре файла сначала записываются и проверяются во временном соседнем каталоге, затем публикуются переименованием. На Windows существующий пустой выходной каталог удаляется непосредственно перед повторным переименованием; при ошибке восстанавливается, если путь ещё свободен. Между этими операциями путь может кратковременно отсутствовать. Непустые каталоги и появившиеся за это время файлы не перезаписываются. NestJS передаёт новый путь и открывает результат только после завершения CLI и собственной проверки файлов.

Успех — exit code 0, JSON-строка `status: completed` в stdout и все четыре файла. Код 2 — параметры/отсутствующие файлы, 3 — некорректные входы, 4 — проблема импорта зависимостей, 5 — проверка/публикация результата, 6 — ошибка расчёта. Ошибки идут в stderr. `--check-environment` проверяет импорты, но не проверяет датасет или интеграцию.

Деньги из float64 организаторов читаются через `Decimal(str(value))` и точно переводятся в целые тиыны без округления; суммы с более чем двумя дробными знаками отвергаются. Повторяющиеся строки транзакций не удаляются. ID в JSON — строки; денежные суммы — десятичные строки KZT. CSV имеют ровно согласованные колонки.

## Проверки

```sh
.venv/bin/python -m unittest discover -s analytics/tests -v
npm run team:check
npm run check:structure
/usr/bin/time -p .venv/bin/python -m money_graph --input-dir data --output-dir artifacts/timed-run-001
```

Основные тесты используют явно синтетические данные и покрывают входы, точные деньги, все шесть правил, изоляты, границу глубины, seeds, воспроизводимость, контракты и сохранность предыдущих результатов. `test_acceptance.py` дополнительно проверяет именно предоставленный набор организаторов: множество gid, точные суммы, изоляты, порядок строк и полный CLI-запуск. Без Parquet эта группа явно пропускается, а не считается успешной приёмкой. По умолчанию файлы ищутся в `data/`; для другого расположения задай `MONEY_GRAPH_DATA_DIR`.

В Windows PowerShell Python-тесты запускаются так:

```powershell
.venv/Scripts/python.exe -m unittest discover -s analytics/tests -v
```

Если текущая учётная запись Windows не может создавать symlink (`WinError 1314`), пропускаются только две проверки настоящих символических ссылок с явной причиной. Проверки обычных файлов, непустых каталогов и ошибок публикации выполняются независимо. Для проверки настоящих symlink без изменения прав Windows запусти тот же набор в Linux-контейнере:

```sh
docker compose --profile tools run --rm --build --no-deps --entrypoint python analytics -m unittest discover -s analytics/tests -v
```

`metadata.elapsed_ms` измеряет время от начала чтения Parquet до готового проверенного снимка перед сериализацией. `total_ms` в stdout включает запись, повторное чтение/проверку файлов и публикацию. Внешний `time` включает также старт Python и импорты; именно он пригоден для доказательства полного запуска менее 300 секунд. Установка/сборка Docker измеряются отдельно и не выдаются за время расчёта.

### Интеграция

Ерасыл вызывает этот же модуль с отдельными каталогами запуска; после exit code 0 проверяет четыре файла. Илья получает контрактный JSON от NestJS: новые API или изменения типов для аналитики не нужны. После слияния backend реальный HTTP-сценарий проверен локально и в Docker; результаты — в [отчёте интеграции](../docs/BACKEND_VERIFICATION.md#интеграция-с-аналитикой--23092026-родион). Frontend включён, его валидатор принимает реальный снимок; полная пользовательская приёмка в браузере остаётся отдельной проверкой.

LLM-as-a-judge пока не подключён. Если позже понадобится аудит, он отдельный и необязательный: методология и синтетические примеры, без исходного датасета; ответы модели не заменяют тесты и не меняют роли автоматически.
