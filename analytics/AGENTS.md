# Аналитика Money Graph

Владелец: **Родион**. Рабочая ветка: `rodion-branch-analytics`.

Перед изменениями выполни проверку участника и ветки из корневого `AGENTS.md`; уже установленную в текущей задаче личность повторно не запрашивай. Эти инструкции дополняют корневые, а не отменяют их.

- Зона ответственности — `analytics/`: Python CLI, данные, метрики, роли, кластеры, приоритеты, экспорты и аналитические тесты.
- Не меняй frontend и backend. Изменения общих контрактов согласуй с владельцами потребителей.
- Изучи `docs/CONTRACTS.md`, `docs/TEAM_PLAN.md`, `docs/prompts/analyst.md`, `docs/METHODOLOGY.md` и материалы организаторов в `docs/references/organizers/` перед изменением правил.
- Команда после установки пакета: `python -m money_graph --input-dir DIR --output-dir DIR`.
- CLI реализует валидацию, правила шести ролей, Louvain, приоритет и четыре согласованных файла. Не создавай фиктивные результаты, не пропускай валидацию и не выдавай готовность CLI за готовность HTTP/UI-интеграции.
- Выходной каталог должен быть новым или пустым. Готовые результаты не перезаписываются; четыре проверенных файла публикуются одной операцией переименования каталога на POSIX/Docker.
- `--check-environment` проверяет только импорты зависимостей; успешная диагностика не означает готовность пайплайна.
- Не выдумывай пороги, роли клиентов или результаты при отсутствии реальных данных. Тестовые fixtures явно отличай от данных хакатона.
- Сохраняй все узлы, точность int64 и денег; учитывай границу depth=4 и неполноту входящих потоков. Выводы — гипотезы.
- Схемы CSV и словарь ролей находятся в `src/money_graph/contracts.py`; общий JSON Schema — в `packages/contracts/analysis.schema.json` от корня репозитория.
- После изменений выполняй `python -m unittest discover -s analytics/tests -v` из корня установленного проекта. Без установки используй `PYTHONPATH=analytics/src python -m unittest discover -s analytics/tests -v`.
