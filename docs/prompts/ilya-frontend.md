## 3. Обязательный API-контракт

- `POST /api/runs`: multipart-поля `nodes`, `edges`, `transactions`, каждый содержит соответствующий Parquet.
- Успешный запуск: HTTP 202, `{run_id, status: "running"}`.
- `GET /api/runs/:run_id`: `{run_id, status, elapsed_ms, error}`.
- Статусы: `running`, `completed`, `failed`; `error` — `null` либо `{code, message}`.
- `GET /api/runs/:run_id/result`: готовый `analysis.json` с `metadata`, `nodes`, `edges`, `clusters`, `top_nodes`.
- `GET /api/runs/:run_id/exports/:filename`: скачивание одного из трёх обязательных CSV.
- Файлы: `nodes_roles.csv`, `clusters.csv`, `top_nodes.csv`.
- Ошибки: неверная загрузка — 400; неизвестный запуск — 404; второй активный запуск — 409.
- Запрос результата до завершения также возвращает 409. Точные поля объектов читай в `docs/CONTRACTS.md`.
- `gid`, `src`, `dst` и элементы `top_gids` — десятичные строки для сохранения точности int64.
- Никогда не преобразовывай идентификаторы в JavaScript `Number`, даже для поиска или ключей графа.
- Денежные суммы KZT приходят десятичными строками: форматируй их без потери точности и округлений через `Number`.

## 4. Реализуй один законченный сценарий

- Выбор трёх Parquet → запуск расчёта → статус → результаты → поиск узла → разбор связей → скачивание CSV.
- Покажи названия выбранных файлов и понятную ошибку, если обязательный файл не выбран.
- Во время расчёта показывай статус и прошедшее время; не придумывай процент готовности, если API его не сообщает.
- После завершения один раз загрузи результат и используй его для карты, таблицы и панели узла.
- При ошибке сохрани понятный контекст: какой запуск завершился неудачно и что вернул backend.
- Опрос статуса прекращается при завершении, ошибке, смене запуска и размонтировании компонента.
- Отделяй результаты разных запусков: ответ старого запроса не должен заменить результат нового запуска.

## 5. Граф и поиск

- Покажи направленный граф; направление перевода должно быть понятно по стрелкам, особенно для выбранных связей.
- Роли и кластеры должны быть различимы. Добавь легенду; при необходимости переключатель окраски «роль / кластер».
- Поддержи все шесть ролей: `consolidator`, `transit`, `distributor`, `terminal`, `coordinator`, `peripheral`.
- Передавай в граф полный список узлов из результата, включая узлы без рёбер; не собирай его только из `edges`.
- Реализуй точный поиск по любому `gid`, выделение найденного узла и перевод камеры к нему.
- Поиск должен находить также изолированные узлы, seeds и узлы на глубине 4.
- Если часть графа скрыта для удобства отображения, найденный узел и доступные связи должны становиться видимыми.
- При выборе узла подсвети соседей, входящие и исходящие связи; используй готовые рёбра из результата.
- Для отсутствующего `gid` показывай явное «Узел не найден», не выбирай похожий идентификатор.

## 6. Таблица и объяснения

- Покажи минимум 20 узлов из `top_nodes` в согласованном порядке приоритета с полем `why`.
- Выбор строки таблицы и выбор узла на графе должны открывать одну и ту же панель подробностей.
- В панели покажи `gid`, роль, кластер, основные метрики, `evidence`, `role_score` и `priority_score`.
- Не смешивай оценки: `role_score` — эвристическая уверенность в роли; `priority_score` — приоритет проверки.
- Не называй эвристическую оценку доказанной вероятностью нарушения или подтверждённой виновностью.
- Кратко объясни ограничения наблюдаемого графа: отсутствие исходящих рёбер не доказывает удержание денег.
- Наблюдаемые входящие и исходящие суммы не являются полным балансом клиента; особенно осторожно трактуй seeds.
- `coordinator` и назначение кластера показывай как гипотезы для проверки, а не установленные факты.
- Покажи предоставленные аналитикой сведения о выбранном кластере: размер, seeds, внутренний оборот, ключевые узлы и гипотезу.
- Скачивай три CSV с backend без повторного расчёта или самостоятельного формирования содержимого.

## 7. Производительность и качество

- Инициализируй Cytoscape только на клиенте: обращение к DOM не должно ломать SSR и сборку Next.js.
- Создавай экземпляр графа один раз на набор данных; освобождай экземпляр и обработчики при размонтировании.
- Не запускай layout на каждом React-рендере, вводе поискового запроса или выборе узла.
- Избегай постоянной анимации; подписи ограничь выделением или подходящим масштабом, если полный граф нечитаем.
- Полный расчёт имеет лимит менее 5 минут; frontend не должен инициировать повторный расчёт при просмотре результата.
- Используй локальные зависимости и assets: работа не должна зависеть от CDN или внешних сервисов.
- Не добавляй авторизацию, чат с AI, дополнительные дашборды, базы данных, Kafka или отдельные очереди.
- Упоминание AI в критериях оценки само по себе не требует LLM: реализуй и честно опиши фактическое решение.
